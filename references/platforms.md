# 电脑、专用浏览器与手机


`--network existing` 在本账本中指可复用且适配本路线的代理节点；电脑分支仍需核对实际本机 HTTP 入口供专用浏览器使用。若客户使用无需代理的普通受支持网络，按正文的实际适用项用本机脱敏文字记录，勿假报 HTTP 端口或服务器检查通过。
先完成 [服务器与网络](network.md) 中节点资料、单独测试和恢复计划的准备。默认电脑链路是 **Karing／v2rayN 的 TUN＋全局接管，系统代理关闭**；AdsPower 另用同一客户端的本机 HTTP 入口。手机导入服务器节点独立连接，不借用电脑回环地址。

**只执行适用设备：**`--computer none` 表示只用手机，直接进入 Android 或 iPhone 分支，不配置 AdsPower；`--phone none` 跳过手机。`--network existing` 复用已核验且有管理／售后入口的现有网络，适用的客户端配置保持原状后检查，不为了匹配本文重装、重新购买或强行替换。现有客户端采用其他已确认模式时记录真实差异，不能将它填成本文的 TUN 配置已通过。

已有 Mac＋Android 免费登录案例；Windows 和 iPhone 仅完成文档路线对照，不能标为已实机验收。本文整理不新增实机、断网或支付测试。未来交付时按当次客户授权检查；未做的检查写“未验证”，已有授权不重复问。安装、网络扩展、UAC、VPN 配置、相机、系统密码、验证码及购买由本人按工具规则确认。

## 1. 按设备进入分支

| 设备 | 客户端和后续路线 | 操作边界 |
| --- | --- | --- |
| Mac | Karing → AdsPower → 可选手机 | 看“关于本机”确认系统和 Apple 芯片／Intel；先保留现有可用 VPN。 |
| Windows | v2rayN → AdsPower → 可选手机 | 在“设置 → 系统 → 关于”读取版本与架构；不要套 Mac 的安装包、权限菜单或 shell 命令。 |
| Android | v2rayNG → 手机浏览器／官方 Claude 应用 | 默认用手机本机步骤；只有受支持的现有设备工具可用时才代操作。 |
| iPhone／iPad | Shadowrocket → 官方 Claude 应用／网页 | 商店下载资格与购买由本人处理；不要求共享或购买他人 Apple 账户。 |

Mac 可按 [Apple iPhone 镜像要求](https://support.apple.com/en-us/120421)检查是否支持；镜像不可用就给手机上的短步骤，不因此阻塞网络配置。Windows 不提供 Apple 原生 iPhone 镜像。不要为了指导安装无关远程控制工具、默认开启 USB 调试或全盘访问。

## 2. Mac：Karing

### 安装与导入

1. **动作：**从 [Karing 官方下载页](https://karing.app/en/download)选择支持本机系统和架构的正式 macOS 包，核对版本、来源及可用摘要／签名。打开下载包，按包内说明安装到应用目录，启动后记录应用版本和实际内核版本。已有 Karing 先读取配置，不覆盖。
   **预期：**应用可启动、版本明确。被系统拦截先核对官方来源及兼容性，再依 macOS 提示由本人确认；不执行关闭 Gatekeeper 或移除全部隔离标记的泛化命令。
2. **动作：**在“添加配置”中选剪贴板／文件导入，把本人保存的节点导入，给它一个不含隐私的名称。展开节点编辑，与服务端逐项核对地址、端口、UUID、Flow、传输、REALITY、SNI、公钥和 Short ID。
   **预期：**目标节点出现且字段一致。导入失败先查链接完整性与支持格式，重新从正确入站导出；不把节点提交在线转换网站。
3. **动作：**先关闭新 Karing 的自动系统代理和 TUN，保留原有网络；在设置中查看 HTTP／mixed 的实际监听地址、端口、认证及路由。新建入口限本机回环，AdsPower 不需要“允许局域网”。
   **预期：**入口可以启动，且使用目标节点。没有入口或端口冲突时保存原值、选择空闲端口后检查，不猜教程常见端口。

可用只读检查辅助核实：本机终端 `lsof -nP -iTCP -sTCP:LISTEN` 查看监听，`scutil --proxy` 查看系统代理。输出可能包含其他应用信息，只摘取相关结果；配置页面与实际监听不一致时以当前进程和请求检查定位原因。[Karing 设置说明](https://karing.app/en/app-manual/settings)

### 接管与 gvisor 分支

按网络文档完成明确指定 HTTP 入口的 HTTPS 请求。测通后复用恢复计划进行交接，逐项检查：

| 动作 | 预期 | 不符合时 |
| --- | --- | --- |
| 解除旧客户端接管，再开启 Karing TUN／Tunnel，完成必要的系统 VPN／网络扩展授权。 | 系统显示对应连接，接口／路由与 Karing 当前状态一致。 | 查未完成授权、内核错误或路由冲突，先恢复旧网再修。 |
| 在路由／代理模式选“全局”，明确固定本次 VPS 节点。 | 本次新请求日志命中该节点，无意外 DIRECT／自动切换。 | 检查例外规则、节点选择与回落；只开启 TUN 不等于全局。 |
| 关闭 Karing 的系统代理，核对 macOS 当前活动网络服务的代理设置。 | HTTP／HTTPS／SOCKS／PAC 没有继续指向旧客户端；Karing HTTP 入口仍在。 | 先辨明原设置归属；不删企业配置或其他无关网络服务。 |
| 读取“设置 → TUN → 网络栈”。新建配置当前支持时可采用 `gvisor`，已稳定配置先保留并记录。 | 保存后连接正常；实际值与记录一致。 | 没有此选项按当前版本资料处理，不修改不相关的 mixed 监听端口。 |
| 脱离旧 VPN 后发起新请求、核对出口，并验证指导对话的新回复。 | 新线路可独立承载实际使用。 | 回旧网，记录“交接未通过”，不把旧网下的成功结果继续复用。 |

**只在 TUN 路径故障时处理网络栈：**若 HTTP 入口可用而 TUN 请求失败，当前栈为 `mixed` 且有 `gvisor` 选项，记录原值后切换、保存、重连，再检查 HTTPS 与实际出口。成功才保留；无效恢复并继续查路由／参数。已经使用 gvisor、没有该选项，或不启用 TUN 的 HTTP 请求也失败时，不重复改栈，回网络文档查服务端、时间和握手字段。

`reality verification failed` 并不能单凭字面证明是网络栈或某个内核版本的问题。旧案例版本与目标只能作为排障线索；先比对实际日志和官方兼容说明，准备原版本／配置备份后才调整，不能默认把所有客户降级。

## 3. Windows：v2rayN

### 安装与导入

1. **动作：**从 [v2rayN 官方发布页](https://github.com/2dust/v2rayN/releases)按 Windows 版本、x64／ARM64 和当前运行库要求选正式包。解压到客户选择的固定可写目录，从解压后的目录启动，记录应用和实际内核版本。
   **预期：**界面与核心都能启动。缺运行库按该版本官方说明补齐；不从压缩包内直接运行，不假定 D 盘存在，不关闭杀毒软件解决启动问题。
2. **动作：**使用“从剪贴板导入分享链接”等当前入口导入节点，选择目标节点，打开编辑页与服务端字段逐项比对。先不开新 TUN 和自动系统代理，保留旧网。
   **预期：**节点存在、字段一致、核心无报错。遇到不支持字段先核对版本，不能删掉安全字段凑通。[v2rayN 官方界面说明](https://github.com/2dust/v2rayN/wiki/Description-of-some-ui)
3. **动作：**在状态栏／设置读取 HTTP／mixed 监听及绑定地址，确认是否认证。用 PowerShell 的 `Get-NetTCPConnection -State Listen` 辅助确认，按 OwningProcess 对照实际进程。
   **预期：**本机入口确由当前客户端监听；局域网共享保持不需要开启。没有监听先查核心日志，端口占用则保存原值后调整。
4. **动作：**用 `curl.exe` 执行网络文档的显式 HTTP 请求，再核对同一路径的出口和日志。
   **预期：**请求走本次节点。TCP 延迟、节点行变色或“测试成功”不能代替这一步；HTTP 认证和握手错误分层排查。

### 接管与恢复

按既有恢复计划切换：解除旧 VPN 接管 → v2rayN 开启 TUN → 全局路由固定目标节点 → 清除／关闭系统代理，保留本机 HTTP／mixed 入口。需要管理员或服务组件授权时由本人处理；不要求整个指导工具始终以管理员运行。不同核心支持的 TUN 栈可能不同，读当前配置和官方说明，不照搬 Karing 的菜单或修复值。

预期：TUN 实际工作，系统代理未指向旧客户端，新请求出口正确，指导对话可收到新回复。TUN 无法启动时先查 UAC／服务状态、适配器与核心日志；仅系统代理可用应记录为临时状态，不能填“TUN 已完成”。

切换后仍依赖旧端口时，在“设置 → 网络和 Internet → 代理”及当前应用配置中查残留代理。代理环境变量可能含认证信息，避免整组打印到聊天；只记录哪些变量／应用仍引用旧入口，按证据修改。不要一键清空所有变量、重置网络或删除全部虚拟网卡。

## 4. Mac／Windows：建立 AdsPower 专用环境

已有专用环境时先读取并复用；本次新建环境不覆盖日常环境。软件从官方渠道安装，费用和账号条件在接入阶段确认。它的作用是独立保存本次浏览器状态并设置明确的代理入口，不是地区资格证明或免验证保证。操作字段参考 [创建环境](https://help.adspower.com/docs/creating_browser_profiles)和 [代理类型](https://help.adspower.com/docs/proxy_types)。

1. **动作：**点“新建环境／New Profile”，用容易识别的名称，如“Claude 专用”。选择当前支持的稳定浏览器内核，操作系统按本机 macOS／Windows 设置；避免复制别人的整个指纹模板。
   **预期：**新增独立环境，原环境未被覆盖。遇到环境数量／订阅限制先核实当前套餐，不自动购买。
2. **动作：**代理类型选 **HTTP**；主机使用刚检查的本机回环地址，端口填客户端实际 HTTP／mixed 端口；用户名和密码只有该入口确实要求认证才填。不要填写 VPS 地址、SSH 端口或 VLESS 入站端口。
   **预期：**“检查代理”可连接，显示出口符合预期。失败查客户端运行、监听、认证、路由，再看服务端；混合入口支持 HTTP 时仍可选 HTTP，不必关闭其 SOCKS 能力。
3. **动作：**在此环境内设置 WebRTC 的禁止／禁用策略和地理位置“不允许”，告知实时音视频及定位功能可能受影响。语言保留客户能用的语言；硬件信息按真实设备和产品支持配置，不为“防封”反复随机化。
   **预期：**保存值与实际页面可观察结果一致。需要相关功能时按客户选择调整并重查受影响项；普通中文界面和中文对话不是失败条件。
4. **动作：**时区使用客户已选且含义明确的方案；需要随出口显示时使用城市时区规则，保留夏令时处理。不要以改时区代替资格确认，也不要把整个系统时钟拨快拨慢。
   **预期：**浏览器报告的时区与所存配置一致。出口城市识别不确定时记录不确定性，不凭 IP 地理库猜精确位置。
5. **动作：**保存后打开这个环境，在这个窗口完成出口、DNS、IPv6 和 WebRTC 检查。可开启该环境适用的“代理不可用不启动”选项；核对是否仅为启动检查。
   **预期：**运行时请求确走预期路径；启动检查不能证明运行中断线必定阻断。[AdsPower 全局设置](https://help.adspower.com/docs/global_settings)

常用检查方法与解释：

| 项目 | 动作与预期 | 不符合／无法观察时 |
| --- | --- | --- |
| 出口 | 在专用窗口打开客户认可的公网地址查询页，发起新请求；与同一时刻 VPS 预期出口在本机比对，并查看节点日志。 | 先查窗口是否正确、代理是否保存、是否有 DIRECT；只记录脱敏结论。单站结果不能代表所有域名。 |
| IPv4／IPv6 | 分别检查能使用的地址族，确认没有预期以外的公网出口。 | 没有 IPv6 记录“当前不可用”；未观察到的路径记“未验证”，不默认关闭整个系统 IPv6。 |
| DNS | 检查客户端 DNS 设置、浏览器安全 DNS与可观察的查询路径。 | DNS 服务商所在地不同并非单独的泄露证据；没有足够证据不下“无泄露”结论。 |
| WebRTC | 在受控检测页面查看是否暴露代理外公网地址，并核对所选限制生效。 | 私网地址、mDNS 名称与公网泄露分开判断；发生不符合预期的暴露先修该环境。 |
| 目标请求 | 打开官方未登录页面，查看本次可见请求命中的节点／规则。 | 页面能开不能证明完整 App 流量；观察不到的部分单列“未验证”。 |

第三方 IP 声誉评分可以辅助记录，不设固定“安全分数”门槛，不据此保证独享、住宅属性、账户安全或可退款。截图留客户本机并遮住完整 IP、邮箱、密钥和账户页面。完成浏览器后接手机；没有手机需求的分支标“不适用”。

## 5. Android：v2rayNG

1. **动作：**从 [v2rayNG 官方项目](https://github.com/2dust/v2rayNG)链接进入 [发布页](https://github.com/2dust/v2rayNG/releases)，选择支持手机系统及 CPU 架构的正式 APK；确认不是仅因排在顶部就选了预发布版。不确定架构时读取手机信息或按该版本提供的通用包说明选择。
   **预期：**来源与包版本明确、安装成功。系统要求允许该安装来源时由本人决定；安装完成恢复不再需要的来源权限。签名冲突先核实已有版本来源与数据备份，不直接卸载丢配置。
2. **动作：**在电脑本人管理的面板显示正确节点二维码，手机点添加／扫码导入；或使用本人控制的本地文件／剪贴板导入。相机权限由本人确认，二维码导入后关闭展示。
   **预期：**节点出现，地址、端口、UUID、传输、Flow、SNI、公钥和 Short ID 与服务器一致。扫码失败先提高本地显示清晰度，不把二维码传给第三方识别服务。
3. **动作：**选中目标节点，在客户端设置使用 **VPN 模式＋全局路由**，检查“绕过”“分应用”“仅代理所选应用”等设置未让本次使用绕开。点连接，首次系统 VPN 请求由本人确认。
   **预期：**客户端连接和系统 VPN 状态一致。没有授权或被其他 VPN 占用时先解决对应提示，不能只按按钮颜色判断。
4. **动作：**手机自己的浏览器发起新 HTTPS 请求、核对实际出口，并依上表检查 DNS／IPv6。再观察官方 Claude 网页／应用的实际可见请求；先做未登录检查，登录后的可用性由账号阶段确认。
   **预期：**手机独立路径符合预期。延迟测试只作辅助；电脑成功不能替代手机检查。网页成功而应用失败时查分应用规则、应用日志和域名路径，不立即换账号。
5. **动作：**出现后台被暂停的证据时，在“设置 → 应用 → v2rayNG → 电池／后台运行”按该厂商菜单允许所需后台运行，解释耗电影响并记录原值。
   **预期：**日常返回应用时连接保持。无需默认关闭整个系统省电或所有应用的电池限制。

Android 的“始终开启 VPN”“无 VPN 时阻止连接”是否可用由系统和客户端决定。这些会影响整机联网，需要客户选择且遵守权限规则；本教程不默认启用，也不因为有选项就宣称已测试保护。设置错导致无网时，先按已保存值恢复该 VPN 的设置，再恢复原网络。

## 6. iPhone／iPad：Shadowrocket

此路线尚未完成真实设备端到端验收。先从 [App Store 的 Shadowrocket 页面](https://apps.apple.com/us/app/shadowrocket/id932747118)核对应用身份、设备要求及客户所在商店可用性；价格和支付以本人商店当时页面为准。已有应用直接复用。下载不可用时先解决官方获取条件，不改填虚假账户资料或使用共享账户。

1. **动作：**打开 Shadowrocket，用扫码或客户端支持的导入入口导入本人节点，选中后进入编辑页，逐项核对服务器地址、端口、VLESS、REALITY、Flow、SNI、公钥和 Short ID。手机不能填写电脑的 `127.0.0.1`。
   **预期：**当前版本支持所需配置且保存完整。字段缺失先查看当前应用说明／版本，不把其他客户端字段名硬填进去。
2. **动作：**在“全局路由”选择 **代理**，选定本次节点，开启连接；添加 VPN 配置、设备密码或 Face ID 由本人完成。
   **预期：**客户端与系统 VPN 均显示已连接。系统询问权限时不能由 AI 代输入设备密码；已有相同授权不重复做添加步骤。
3. **动作：**在手机自己的浏览器检查新 HTTPS 请求和出口，核对 DNS、IPv6、排除路由；再检查本次实际使用的 Claude 网页／应用可观察路径。
   **预期：**手机请求符合预期。TCP 延迟正常而 CONNECT／网页失败时先查握手、导入字段、两端时间及日志，区分端口可达与代理可用。
4. **动作：**若证据指向 TLS 指纹兼容问题，记录旧值，只尝试当前版本实际支持且有依据的一项指纹，保存重连，再试原失败请求。
   **预期：**原故障和出口检查一并恢复才保留；无效恢复。旧资料的“Chrome 140”只是尚未确认效果的反馈线索，不作默认修复值、不循环试指纹、不盲目降级。

“代理”模式不证明全部系统请求无绕行，也不代表关闭 VPN 后仍断网。手机掉线时先停止相关应用操作，恢复连接并复查再继续。不要为普通节点导入安装 HTTPS 解密根证书或启用中间人解密。

## 7. 时钟、时区和定位

网络通畅后分开检查这些设置，不把它们作为隐藏真实资格的手段。优先保留正确自动校时；本地时区按客户实际使用需求选择，浏览器的单独时区设置单独记录。需要修改系统显示时区时先解释日历、提醒和地图的影响，复用已确定的选择。

| 系统 | 动作 | 预期与分支 |
| --- | --- | --- |
| macOS | “系统设置 → 通用 → 日期与时间”查看自动校时和时区；需固定时区时只关闭自动时区并选城市。自动时区仍被定位改变时检查“隐私与安全性 → 定位服务 → 系统服务 → 设定时区”。 | 当前真实时间正确，时区规则符合选择。定位总开关保持客户需要的状态；不要为浏览器权限默认关闭所有定位。 |
| Windows | “设置 → 时间和语言 → 日期和时间”保留自动设置时间；若需手动时区，关闭自动时区，选择相应区域，检查夏令时。可用 `Get-TimeZone` 只读确认。 | Windows 名称与 IANA 名称可能不同，按规则比对。定位权限在系统“隐私／隐私和安全性 → 位置”按客户需求控制。 |

AdsPower 地理位置权限与手机／系统定位开关分别记录。关闭定位可能影响地图和找回功能，不是 Claude 免费登录的统一前提。语言可保留中文；UTC 偏移会受夏令时影响，不把某城市全年固定成同一偏移。

## 8. 手机网络切换、日常使用与退出

Wi-Fi 与蜂窝是不同网络路径。客户实际要用哪一种就在该网络下单独记录；未使用的另一种记“不适用，启用前再查”，不把 Wi-Fi 的检查结果当蜂窝结果。没有授权本次实机测试时只保存待检查步骤。

日常启动顺序：启动客户端并确认目标节点 → 检查连接与出口 → 打开已配置的 AdsPower 环境或手机应用。最小化客户端不等于退出；系统重启后需重新确认客户端、TUN、实际 HTTP 端口和环境代理。常规交付不强制重启，只有遇到重启后故障再针对性排查。

退出或恢复原网络：

1. 保存当前工作并关闭需要本次代理的网页／应用。电脑先关闭专用浏览器环境，避免它在入口消失后继续请求。
2. 关闭新客户端连接／TUN，再按记录恢复旧客户端或原本的网络设置。普通客户端退出可能恢复直连，也可能留下显式代理设置；不要把任一结果自动称为保护生效。
3. 不能联网时读取当前代理和路由，只撤销本次改动。手机若开启过系统“无 VPN 阻止连接”，按保存值恢复；不要删除全部 VPN 或重置整机网络。
4. 用新请求确认恢复。下一次使用 Claude 前重新启动已配置线路，检查后继续；账号与付款问题转 [账号与付款](accounts-payment.md)。

没有实测的节点故障／客户端退出行为如实记“未验证”，客户明确接受此限制即可保留记录，不擅自加装高权限防火墙或自检面板。若另行授权做断线保护测试，按网络文档分别验证故障场景并立即恢复；仅开启全局、显式 HTTP 或启动前代理检查都不能替代结果。

本阶段交付记录至少包括：每台设备的系统／客户端／内核版本、目标节点别名、当前接管模式、实际 HTTP 入口（电脑）、专用环境名称、各设备出口及 DNS／IPv6／WebRTC 的可观察结果、时间设置、恢复操作、未验证项。敏感值只在客户本机私密配置中保存，进度说明只留脱敏依据。

# 服务器与网络


`--network existing` 在本账本中指可复用且适配本路线的代理节点；电脑分支仍需核对实际本机 HTTP 入口供专用浏览器使用。若客户使用无需代理的普通受支持网络，按正文的实际适用项用本机脱敏文字记录，勿假报 HTTP 端口或服务器检查通过。
本文交付的是一条由客户自己管理的连接：电脑或手机的代理客户端连接 VPS 上的 Xray。电脑另向专用浏览器提供本机 HTTP 入口。先读 [接入与交付](intake-handover.md)，完成当前资源、费用、服务资格与恢复方式的确认；已有可用配置先核验复用。

**先选实际分支：**已有网络或节点，且客户能确认使用权限、当前可用状态与管理／售后入口时，进度选择 `--network existing`，跳过购买和部署服务器，继续检查实际使用设备。没有电脑需求时选择 `--computer none`，跳过桌面客户端和 AdsPower，直接做手机分支。仅手机但还需新建 VPS 时，可用服务商官方网页终端或客户已有受支持的 SSH 工具完成服务器步骤；工具不能安全处理的部分明确留待办，不虚构执行结果。

**网络可连接不代表本人符合 Claude 的可用地区、账户或付款条件。**进入账户步骤前仍须核对 [Claude 官方可用地区](https://support.claude.com/en/articles/8461763-where-can-i-access-claude)。不要靠修改地区字段或检测网站评分替代资格核对。

本版依据公开技术文档独立编写。已有 Mac＋Android 免费登录案例不能证明所有网络、系统版本或订阅都可用；Windows／iPhone 只有文档路线对照。本次文档整理不进行客户设备、新服务器或断网测试，验收状态见 [验证记录](../VALIDATION.md)。下面的检查供实际交付时按客户授权执行。

## 1. 先把要用的资料留在客户本机

执行助手先查看现有进度，只补缺项。客户已授权的安装、配置或修复继续完成；系统权限、凭据输入、验证和购买按工具规则由本人确认，不重复索要同一动作的许可。

| 本机私密配置记录 | 用途与检查 |
| --- | --- |
| VPS 控制台入口、实例名称、系统、架构 | 控制台由客户持有；确认能进入救援／串口／网页终端，避免 SSH 中断后无从恢复。 |
| 服务器地址、SSH 用户和实际端口 | 来自服务商控制台，不默认用户为 root、端口为 22。 |
| 密码或私钥的保存位置 | 密码交由本人输入；只记录私钥文件路径，不读取或上传其正文。 |
| 现有代理客户端、节点别名和接管方式 | 写清恢复哪个应用、哪个连接以及原系统代理／TUN 开关。 |
| 服务端版本、入站及导出资料 | 包含节点凭据的原件仅在客户私密位置保存；公共进度只记版本、是否一致和脱敏结果。 |

预期：客户能自行找回旧网络，也能进入 VPS 管理控制台。缺恢复入口时先补入口；不要先退出仍支撑对话的 VPN。节点 URI、二维码、面板密码、SSH 私钥都按凭据处理，不贴聊天、不入仓库、不交给在线转换器。

先分清四种端口：

| 端口 | 连接方向 | 是否应写入 AdsPower |
| --- | --- | --- |
| SSH | 电脑 → VPS，管理 Linux | 否 |
| 3x-ui 网页管理 | 管理入口 → VPS 上的面板 | 否 |
| VLESS 入站 | Karing／v2rayN／手机客户端 → VPS | 否 |
| 本机 HTTP／mixed | AdsPower → 同一台电脑的代理客户端 | 是，先查当前实际值 |

端口范围为 1–65535，不同服务不要占用同一监听地址上的同一端口。`mixed` 监听可同时支持 HTTP 和 SOCKS；它与 TUN 网络栈的 `mixed` 是两回事。

## 2. 准备或复用 Debian 12 VPS

**动作：**已有 VPS 先查看系统和现有服务。新购时在客户选定服务商的官方控制台核对地域、CPU 架构、内存、磁盘、流量、超额计费、续费与退订条件；由客户支付。此路线选 Debian 12（bookworm）和有对应软件包的 amd64／arm64 架构，电脑是 Windows 也不需要 Windows Server。购买规模按实际客户端数和官方软件要求确定，不承诺某一低价套餐一定够用。

**预期：**实例运行、IPv4 和 SSH 资料可用、能够打开恢复控制台。Debian 12 已进入 LTS，官方公布的支持期截至 2028 年 6 月 30 日；维护时还要检查架构和软件包是否在支持范围内。[Debian 12 发布信息](https://www.debian.org/releases/bookworm/)

**异常：**服务商不提供该系统时先查看现有受支持方案；不要为了套教程重装有数据的实例。新系统安装、重装或更换地址的影响先写清，破坏性动作依工具规则处理。VPS 只有 IPv6 而本地缺少可用 IPv6 路径时，先解决地址方案，不能照抄 IPv4 操作宣称完成。

## 3. 从电脑登录服务器

以下含尖括号的命令是模板。执行助手先用实际值生成本次命令，再运行；不要把占位符原样交给终端，也不要在命令行写密码。

**在 Mac 本机终端／Windows 本机 PowerShell：**先用 `ssh -V` 确认 OpenSSH 可用，再按认证方式选一条：

```text
ssh -p <实际SSH端口> <登录用户>@<服务器地址>
ssh -i "<私钥完整路径>" -p <实际SSH端口> <登录用户>@<服务器地址>
```

首次连接把主机指纹与服务商控制台或其他可信渠道对照，再确认。已知主机密钥突然变化，先核实重装／迁移记录，不直接删 `known_hosts` 解除告警。Mac 私钥权限过宽时只对所用文件执行 `chmod 600 "<私钥完整路径>"`；Windows 在文件“属性 → 安全 → 高级”核对所有者、继承与访问主体，按 OpenSSH 要求收紧该文件 ACL，不照搬 `chmod`。不存在 `ssh` 时按系统官方方式安装 OpenSSH 客户端，不为此额外安装 WSL。

**预期：**能进入 Linux 会话。继续在 **VPS 的 Linux 终端**读取：

```sh
cat /etc/os-release
uname -m
id
timedatectl status
ss -lntup
```

确认系统、架构、当前权限、时间同步与现有监听，区分本机窗口和远端窗口。非 root 会话按实际权限使用 `sudo`，缺权限则由客户完成授权。

**异常：**连接超时先查实例状态、地址、SSH 端口和服务商安全组；拒绝认证先核对用户名与凭据类型；密钥权限报错只修目标文件；系统与预期不符先停下部署，保留原服务。不要把 `apt` 或 `systemctl` 在本机 PowerShell 执行。

## 4. 安装／检查服务端管理组件

本路线用 **3x-ui 管理 Xray**。已有合适的 Xray 管理方式可直接检查、导出，不必为了阅读本文加装面板；额外自检网页和新防火墙不是默认安装项。3x-ui 与 Xray 是不同组件，分别记录版本。参考入口为 [3x-ui 官方项目](https://github.com/MHSanaei/3x-ui)、[官方文档](https://docs.sanaei.dev/docs/) 与 [Xray 官方发布页](https://github.com/XTLS/Xray-core/releases)。

### 4.1 先备份和审阅，再运行安装器

1. **动作：**检查是否已有 3x-ui、Xray、占用端口和业务；有则备份当前配置、数据库及版本，记录如何恢复。全新 Debian 主机可在 VPS 中运行 `apt update`，确认没有仓库错误后安装所需 `ca-certificates`、`curl` 和 `tar`；只有确有需要时补其他包。不要顺带全量升级、重启或改 SSH。
   **预期：**安装前状态可恢复，依赖齐全。包管理失败先查 DNS、仓库与锁持有进程，不删锁文件或反复换源碰运气。
2. **动作：**在官方 Releases 选择当前支持该系统的正式版本，保存发布页、版本标签／提交和架构。找到该版本安装器，下载到本地文件，检查完整内容及其继续下载、改写服务、开放端口和自启动的行为。下载可用 `curl --fail --location --output install.sh '<已核实的官方固定版本脚本URL>'`；这是下载模板，不是安装命令。
   **预期：**来源、版本和安装影响明确；有官方摘要／签名时核验。只计算本地摘要不能独立证明来源。下载不是脚本、发生未知跳转或内容未审阅时停止执行。
3. **动作：**审阅通过后才在 VPS 上以所需权限执行已保存的脚本，例如 `bash ./install.sh`，并按该版本支持的方式固定安装版本。若脚本仍会取“最新”组件，先弄清它如何指定版本和回滚，不假定脚本标签等于最终内核版本。不执行 `curl … | bash` 或把远端响应直接交给 shell 的等效命令。
   **预期：**安装日志没有失败，面板和 Xray 实际版本可读取。失败保留错误和原配置，不反复覆盖安装。
4. **动作：**使用生成的高强度管理密码和非默认管理路径，放入客户密码管理器。查看当前安装器或 `x-ui` 菜单中的实际名称，不按旧文档的菜单数字点选。
   **预期：**登录资料可找回，面板服务状态正常。凭据不明先用已有管理入口恢复；404 先查完整基础路径，不直接重置整个配置。

### 4.2 管理入口与业务端口分别处理

新建且支持配置的面板优先监听 VPS 回环地址，通过 SSH 转发管理，避免为管理额外开放公网端口。先确认面板实际协议、监听端口和基础路径。

**电脑本机另开终端，保持原 SSH 会话：**

```text
ssh -N -L 127.0.0.1:<空闲本地管理端口>:127.0.0.1:<实际面板端口> -p <实际SSH端口> <登录用户>@<服务器地址>
```

密钥登录增加对应 `-i` 参数。预期转发会话保持运行；浏览器按实际协议打开 `127.0.0.1` 的本地端口并带完整面板路径。HTTP 经 SSH 隧道传输；面板若启用 HTTPS，保留其 TLS 验证要求，按实际证书主机名安排访问，不关闭校验凑通。已有公网 HTTPS 管理入口先核对证书、访问限制和续期，不无故改成 HTTP。

打不开时依次查：SSH 转发是否还在、端口是否被占用、面板是否监听、协议是否匹配、路径是否完整。若需要公开管理入口，先配置适用的 HTTPS 和访问限制；不要把管理密码经明文公网 HTTP 提交。只有采用需要外部端口验证的证书方案时才安排其验证端口，不为 VLESS REALITY 本身自动开放 80 端口。

在 VPS 中读取服务状态及本次错误；常见服务名为 `x-ui`，实际不同时按已安装的服务名称：

```sh
systemctl status x-ui --no-pager
journalctl -u x-ui --since "10 minutes ago" --no-pager
ss -lntup
```

日志可能含地址或配置，只把必要的脱敏错误写入进度。检查云安全组和当前主机过滤规则，仅为实际 VLESS 入站放行相应 TCP 端口；保留 SSH 管理通道。不默认安装或重置 UFW，不执行清空防火墙命令。若现有过滤器无需变更，记录即可。

## 5. 建立一个可核对的 VLESS＋REALITY 入站

在 3x-ui 的入站列表新增本次节点。填写前检查当前 Xray／面板是否支持这些字段；按钮改名时读取当前帮助，不猜位置。基础路线用 VLESS＋TCP（新版本可能称 RAW）＋REALITY；不要将模板机械套在其他传输上。

| 项目 | 本次设置与验证 |
| --- | --- |
| 备注、启用状态 | 取不含个人信息的节点别名，保存后检查启用。 |
| 地址与入站端口 | 地址来自实例；选未占用的合法 TCP 端口，与 SSH／管理面板区分。 |
| VLESS 客户端 ID | 生成本次 UUID；不复用文档示例。流量限额和到期时间按客户实际方案设置，避免导出后立即失效。 |
| 传输与 Flow | TCP／RAW；本路线两端支持时使用 `xtls-rprx-vision`。一端不支持则先解决版本／兼容方案，不能单方面留空。 |
| REALITY 目标 `target`／旧称 `dest` | 从 VPS 能访问的合适 TLS 服务中选择，填写目标主机和端口；依据当前官方要求检查 TLS 和证书，而非盲填固定网站。 |
| 服务端 `serverNames` 与客户端 SNI | 选目标证书有效且实际接受的名称；客户端 SNI 必须与服务端允许列表匹配。不要把 VPS 地址误写成目标 SNI。 |
| 密钥与 Short ID | 用面板当前生成工具或对应 Xray 工具生成；服务端保留私钥，客户端使用公钥／当前字段对应的值。Short ID 从服务端允许列表选取，不能抄图或猜字符。 |
| 指纹、版本限制等 | 选当前客户端支持的 TLS 指纹。`minClientVer` 为可选限制，不把旧案例的值当作普遍要求；不理解的高级字段保留兼容默认值。 |

REALITY 字段名称和目标要求以 [Xray REALITY 官方配置](https://xtls.github.io/config/transports/reality.html) 为准。客户端与服务端字段并非逐项相同，服务端的 `target` 和私钥不能复制进客户端。目标域名可变，选择 CDN 目标还应阅读官方对回落流量的说明。不要因为某旧版本曾成功就自动降级当前内核。

**保存后预期：**入站启用，Xray 无配置错误，`ss -lntup` 能看到期望监听，云安全组及已有主机过滤规则允许本次业务端口。客户端真正连通还需下一节验证；端口可达或延迟有数值只证明部分链路。

**异常：**服务起不来先读配置校验和日志，查端口冲突、缺失密钥、字段不兼容；不要同时随机更改多个参数。若改动影响共用内核下其他入站，恢复原配置并记录受影响范围。

## 6. 导出、单独验证，再交接网络

### 导出给客户端

在目标入站的客户端条目导出分享 URI 或二维码，直接导入 [设备文档](platforms.md)中的客户端；手机可在本人设备上扫描。逐项对照服务器地址、入站端口、UUID、传输、Flow、REALITY、SNI、公钥和 Short ID；导入后再次打开编辑页检查，不用截图识别长密钥。预期字段与服务端一致；缺字段重新从正确条目导出，不手工猜补。

### 独立检查新入口

保留旧网络，先让新电脑客户端只提供回环 HTTP／mixed 入口，暂不开新 TUN 或系统代理。读取实际监听地址、端口和认证要求。用明确指定该入口的新 HTTPS 请求，加本次客户端日志，检查确实使用目标节点；若旧网络仍承载客户端到 VPS 的连接，只能记录“经当前网络可连”。

本机请求模板如下；Mac 用 `curl`，Windows PowerShell 用 `curl.exe`，避免旧版别名歧义：

```text
curl --proxy "http://127.0.0.1:<实际HTTP端口>" --noproxy "" --connect-timeout 10 --max-time 30 -I https://example.com/
```

HTTP 入口也能通过 CONNECT 访问 HTTPS，不应仅因目标是 HTTPS 就把入口协议改成 `https://`。入口有认证时按客户端实际机制本地输入，不把密码拼进命令或报告。随后用同一入口访问客户认可的公网地址检测服务，在本机比对实际出口与 VPS 出口；检测服务会看到此次公网地址，不上传节点凭据。

预期：新请求成功、请求日志命中正确节点、出口匹配。失败依次查本机监听、代理认证、节点启用、服务端端口和握手日志；HTTP 不通时先修配置。仅在确证当前入口不支持／不兼容 HTTP 而 SOCKS5 已实际验证可用时采用备选，记明理由及 DNS 路径。

### 交给新线路接管

1. **动作：**把恢复步骤按本次真实应用填好并展示：“先停新客户端的连接／TUN，再打开原客户端、选原节点、恢复原代理模式，回到对话继续。”保存“切换待验收”。
   **预期：**客户可在对话断开时独立恢复；若当前工具无法安全完成切换，停在已有可用状态，给用户短步骤。
2. **动作：**按设备文档解除旧客户端接管，开启新客户端 TUN＋全局、固定目标节点，关闭系统代理，保留 HTTP 入口。避免两个 TUN 同时争抢路由。
   **预期：**虚拟接口和路由存在，新客户端正在接管。失败先恢复旧网络，不重复做同一无效切换。
3. **动作：**在旧 VPN 不再承载测试流量的状态下，用不显式设置代理的新请求核对出口，再测 HTTP 入口与原先失败操作。检查应用是否仍缓存旧端口或使用代理环境变量，按证据修正。
   **预期：**两条检查路径都符合预期；如果指导对话依赖这条网络，由客户发新消息并收到新回复。恢复旧 VPN 后收到的回复不能证明新线路通过。

## 7. 故障分支与恢复边界

| 症状 | 下一动作 | 成功依据／恢复 |
| --- | --- | --- |
| 面板能开，节点握手失败 | 对照两端字段、时间、入站状态和最新错误；只修发现的问题。 | 新 HTTPS 请求和出口通过；否则还原本次改动。 |
| HTTP 入口可用，开 TUN 后失败 | 查网络扩展／权限、路由、排除规则和两个客户端冲突；Mac 按设备文档检查 gvisor。 | 脱离旧 VPN 后的新请求成功，不能只看 TUN 开关。 |
| 关旧 VPN 后新线路失败 | 先恢复旧连接，查新客户端到 VPS 的直接传输路径，不能沿用旧 VPN 下的测试结果。 | 重做交接三步；未通过保存具体错误并保留旧网。 |
| REALITY 错误反复出现 | 查版本发布说明、目标可用性、SNI、密钥、Short ID 和时间；有兼容性证据再安排版本变更。 | 一次改一组有依赖的参数，保存原版本和配置，失败回滚。 |
| 退出客户端后上不了网 | 区分显式代理入口消失、遗留系统代理／路由和已配置的阻断规则。 | 只恢复本次改动；不一键网络重置，不清空防火墙。 |
| 退出客户端后变回直连 | 这是可能的系统行为，先停止需要该线路的网页／应用操作。 | 恢复客户端并复查后继续；不能称为已具备断线保护。 |

常规交付不自动安排重启、切断节点或退出客户端的破坏性验证。客户明确不做实机测试时只对照配置和资料，相关结果记“未验证”。如客户另行授权断线行为测试，先停止登录／付款工作，复用既有恢复计划，分别检查“节点不可用而客户端仍运行”和“客户端退出”，每项后立即恢复。没有实测不能把“全局”“VPN 图标”或显式 HTTP 代理写成系统级断线保护。

服务端回滚：保留 SSH 和控制台入口，恢复本次变更前的数据库／配置及匹配的程序版本；先校验再重启对应服务，只撤销本次增加的端口规则，不删除旧入站。客户端回滚：停新接管，按保存值恢复旧客户端和系统代理，再确认新请求及对话恢复。不要卸载全部网络软件作为排障第一步。
